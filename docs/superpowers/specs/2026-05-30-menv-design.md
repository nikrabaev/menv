# menv — Environment Variable Manager (TUI)

**Date:** 2026-05-30
**Status:** Approved design, ready for implementation planning

## Problem

Across a monorepo with several apps and docker-compose services, it is hard to
remember which environment variables each app requires, to keep shared and
app-specific values separated, and to keep real secret values out of plaintext
`.env` files. `menv` is a modern terminal UI that discovers, organizes,
encrypts, and regenerates `.env` files across a repo from a single source of
truth.

## Goals

- Aggregate every `.env` / `.env.example` in a repo into one observable view.
- Detect pnpm and bun workspaces and docker-compose files; understand which
  variables are passed to which apps and containers.
- Store variable **values** in encrypted, separate files; keep **structure**
  (names, descriptions, grouping, wiring) in committable plaintext.
- Let the user group, filter, and describe variables, and wire variables to
  docker services easily.
- Require an **explicit save**; on save, regenerate the affected `.env` files
  from scratch and replace them.
- Be runnable as a single terminal command: `menv`.

## Non-goals (v1)

Deferred to v2 (design must not preclude them):

- Code scanning / drift detection (variables used in source but undeclared, and
  declared-but-unused).
- Variable **types** (string / array / json with JSON-schema validation).
- Team key-sharing UI (the storage format already supports multiple recipients).
- Cross-platform secret storage (Linux/Windows keychains).
- Git diff / history views of values.

## Key decisions

| Topic | Decision |
|---|---|
| Secret store purpose | Local safety net in v1, **designed for team-sharing later** ("both"). |
| Encryption model | **age** (X25519, multi-recipient). v1 recipient = local key. Add teammates' public keys later → re-encrypt + commit vault. No re-architecture. |
| Environments | **First-class**: a value is keyed by `(variable, environment)`. |
| Variable scoping | **Two explicit tiers** — `global` (shared pool) and `local` (owned by one app). **No automatic override chain.** |
| Discovery | **Files only** in v1 (workspaces, `.env*`, docker-compose). Code scan = v2. |
| TUI stack | **Ink** (React for the terminal). |
| Main layout | **Three-pane**: scopes · variables · inspector. |
| `.env.example` | Regenerated by menv as a committed, **values-free** template. |
| Compose wiring | Default to **`env_file`** (point service at a generated `.env`); only touch inline `environment:` when the user adds an inline var. |
| Values storage | **All** values live in the encrypted vault; manifest holds structure only. |

## Data model

```
Variable
  name        string
  tier        "global" | "local"
  ownerApp    AppId            # required iff tier == "local"
  description string
  group       string | null    # user-defined logical category
  secret      boolean          # controls on-screen masking + .env.example omission

Value
  variableId  VarId
  env         EnvId            # one value per (variable, environment)
  value       string           # stored encrypted; no per-consumer override

Environment
  id          EnvId            # e.g. "dev","staging","prod"
  default     boolean          # exactly one default

Consumer (target that receives generated output)
  App     { id, name, path, envFileMap: { EnvId -> filename } }
  Service { id, name, composeFile, inject: "env_file" | "environment", envFileRef? }

Wiring
  variableId -> Set<ConsumerId>   # global: explicit; local: auto-includes owner app
```

Value resolution is intentionally flat: the value emitted for a variable to any
consumer in a given environment is simply `Value(variable, env)`. A `global`
variable resolves to the same value for every consumer it is wired to. There is
no per-app/per-consumer override layer (per the "two tiers, no chain" decision).

## On-disk layout

```
repo/
├─ menv.toml                  # committed: environments, apps, services, recipients, settings
├─ .menv/
│  ├─ manifest.toml           # committed: variable defs, tiers, groups, descriptions, wiring
│  ├─ values/
│  │  ├─ dev.env.age          # encrypted values per environment (JSON keyed by variable id)
│  │  ├─ staging.env.age
│  │  └─ prod.env.age
│  └─ backups/                # gitignored: pre-save snapshots (safety net)
├─ apps/web/.env              # GENERATED, gitignored
├─ apps/web/.env.example      # GENERATED for apps with a real .env; committed; example values
└─ docker-compose.yml         # menv edits env_file / environment for wired services
```

- **Committed:** `menv.toml`, `.menv/manifest.toml`, every generated `.env.example`.
- **Gitignored (v1):** `.menv/values/*.age`, `.menv/backups/`, all generated `.env`/`.env.<env>`.
- Going team (v2): flip a setting to commit `.menv/values/*.age` (safe — age-encrypted).
- `menv init` writes/updates `.gitignore` accordingly.

## Encryption

- Library: `age-encryption` (pure-TS age). X25519 multi-recipient envelope;
  interoperable with the standard `age` CLI.
- Recipients listed in `menv.toml`. v1: the local user's public key only.
- Identity (private key) stored in the **macOS Keychain** via the `security`
  CLI (no dependency). Fallback: a scrypt-passphrase-encrypted identity file at
  `~/.config/menv/identity`.
- On launch: load identity → decrypt vault into memory. On save: re-encrypt
  affected environments to all recipients.
- Fallback plan if `age-encryption` misbehaves on Bun (validated during build
  spike): a libsodium-style envelope — random AES-256-GCM data key, wrapped
  once per recipient via X25519 — same multi-recipient model.

## Discovery (v1, files only)

On launch (or `menv init`), find the repo root (walk up for `menv.toml`, else
`.git` / workspace files), then:

1. **Workspaces → apps.** Parse `pnpm-workspace.yaml` and `package.json`
   `workspaces` (bun). Each package dir is a candidate App.
2. **Env files → variables + values.** Glob `.env`, `.env.*`, `.env.example`
   (skip `node_modules`). Keys → variables; a `#` comment directly above a key
   is imported as its description. File→environment is inferred
   (`.env`→default, `.env.staging`→staging) and confirmable.
3. **Compose → services + wiring.** Parse `docker-compose*.y(a)ml`. For each
   service read `env_file:` (those vars wired to the service) and `environment:`
   (inline vars). Services become Consumers.
4. **Import.** First run writes structure to the manifest, encrypts current
   values into the vault, then regenerates the now-managed files in canonical
   form.

Ambiguous cases (a var present in two apps — global or two locals? a `.env` with
no owning workspace) get sensible defaults and are **flagged in the TUI for
confirmation**, never silently guessed.

## Save flow (explicit)

Edits are staged in memory with a `● N unsaved` indicator. On `s`:

1. **Validate** (required-but-empty values, name collisions).
2. **Back up** every file about to be overwritten → `.menv/backups/<timestamp>/`.
3. **Persist structure** → write `manifest.toml` + `menv.toml`.
4. **Encrypt values** → rewrite `values/<env>.age` for affected environments.
5. **Regenerate from scratch** → per app, write its `.env` for each environment
   (only wired vars, grouped, with description comments) and a values-free
   `.env.example`; per wired service, update compose `env_file`/`environment`
   (prefer `env_file`; preserve comments via the YAML Document API).
6. Write atomically (temp + rename), clear staged state, show a summary.

`q` with unsaved changes prompts to discard. Backups provide an escape hatch
since menv overwrites files it owns.

## TUI (Ink, three-pane)

**Regions:** Top bar (repo · env switcher · dirty indicator) · Left scopes tree
(`All`, `Root`, then dimmed `APPS` / `SERVICES` / `GROUPS` section headers with
their members) · Middle variable list (badges: `🔒`
secret, `●` unsaved; `/` filter) · Right inspector (tier, group, secret, wired
consumers, **values per environment** with "— not set" gaps shown).

**Components** (each small, single-purpose, independently testable):

| Component | Job |
|---|---|
| `App` | root layout, global keymap, mode routing |
| `TopBar` | repo + env switcher + dirty indicator |
| `ScopeTree` | left nav, selection state |
| `VariableList` | filtered list + cursor |
| `Inspector` | detail render for one variable |
| `EditValueModal` | edit a value for the current env |
| `NewVariableModal` | create var (name, tier, group, secret) |
| `WireModal` | toggle which apps/services a var targets |
| `EnvSwitcher` | pick active environment |
| `SaveSummary` / `ConfirmDiscard` | save report / quit guard |
| `HelpOverlay` | keybindings |

**Key map:** `↑↓`/`tab` navigate · `/` filter · `e` env · `g` group · `n` new ·
`w` wire · `d` toggle secret · `⏎` edit value · `x` delete · `s` save · `?`
help · `q` quit.

## Architecture / layering

A thin TUI over a headless core, so file I/O and crypto are testable without
rendering, and `menv generate` reuses everything except `ui`:

- **`core`** — model, types, value resolution, staging/diff logic.
- **`io`** — discovery; dotenv / compose / toml parsers; file generators.
- **`crypto`** — age vault (encrypt/decrypt, recipients, keychain identity).
- **`store`** — in-memory state (loaded model + staged-changes diff); the single
  thing persistence talks to.
- **`ui`** — Ink components.

## Tech stack

- **Runtime/lang:** Bun + TypeScript.
- **TUI:** Ink (React) + `ink-text-input`; remaining components custom.
- **Discovery/parsing:** `Bun.Glob` (built-in); a small hand-written dotenv
  parser (captures `#` comments as descriptions, round-trips cleanly); `yaml`
  (Document API) for docker-compose; `smol-toml` for `menv.toml` / `manifest.toml`.
- **Crypto:** `age-encryption` (+ libsodium-style fallback); macOS `security`
  CLI for keychain.
- **Testing:** `bun test`; `ink-testing-library` for UI smoke tests.

## Packaging & commands

Command name: **`menv`**.

- `menv` — launch the TUI in the current repo.
- `menv init` — scaffold config, import existing env files, set up keys +
  `.gitignore` (auto-offered on first run if no config).
- `menv generate [--env <e>]` — headless regenerate all env files from the vault
  (CI / scripts), no TUI.

Dev install via `bun link`; portable single binary via
`bun build --compile --outfile menv`.

## Open questions / risks

- `age-encryption` behavior on Bun — validate in an early spike; fallback ready.
- Editing `docker-compose.yml` while preserving comments/formatting — use the
  `yaml` Document API; prefer `env_file` wiring to minimize compose churn.
- Faithful round-trip of existing `.env` files (comments, ordering) on import →
  regenerate; mitigated by backups and a values-free `.env.example`.
